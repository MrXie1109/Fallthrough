# 09 模块

> [English](09-modules.md)

## 范围

本篇规定模块的导入与导出、`module` 块与 `use` 声明、导出表的内容、名字身份规则、
模块查找顺序、多文件编译与链接。

## 模块与导入

### 模块是什么

`.ftm` 文件是一个模块。`module` 块是同一件东西写在文件内部：

```ft
// counter.ftm
internal int = 0;

export fn get() int {
    return internal;
}

export fn set(i int) void {
    internal = i;
}

export type Point {
    x int;
    y int;
}

export fn sum(this &Point) int {
    return this.x + this.y;
}
```

```ft
// main.ft
module shapes {
    sides int = 4;

    export fn count() int {
        return sides;
    }

    export type Square {
        side int;
    }

    export fn area(this &Square) int {
        return this.side * this.side;
    }
}
```

1.1.1 模块是容器加可见性边界。除该边界外它不引入作用域：`module` 块的成员是包含该块
的文件中的声明，适用于与块外声明相同的规则。

1.1.2 `module` 块中未经 `export` 声明的成员，**不得**通过写在块外的名字访问。

1.1.3 导入不嵌套。`import M;` 使 `M` 的全部内容作为一个名为 `M` 的平铺模块可用；它不
把 `M` 的内容放入一个指代 `M` 的块。无论有多少文件导入，一个模块**必须**只解析一次。

1.1.4 模块中的声明**必须**在该模块内以其自身名字、不加限定地访问。该规则适用于模块的
签名，导入者从声明模块读取它们。

### 形式

```ft
// geom.ftm
export fn area(w int, h int) int {
    return w * h;
}

export type Point {
    x int;
    y int;
}
```

```ft
// PHONY：`geom` 是本节描述的模块，它的内容分成两个文件，无法作为单个
// 代码块编译。
import C;
import geom;
import geom as g;
from geom import area;
from geom import Point;

// main.ft

fn main() int {
    p Point = .{1, 2};
    C.printf("%d %d %d\n", area(2, 3), g.area(3, 4), p.x);
    return 0;
}
```

这两个文件一起编译，程序输出 `6 12 1`：`geom.area` 既能经模块名调用，也能经别名 `g`
调用，而 `from geom import area` 让裸名字可用。

模块可以把导入的东西再导出，伞形模块就是这样拼起来的：

```ft
// umbrella.ftm
export from geom import *;
```

2.1.1 导入是静态的：模块在编译期加载，不存在运行期模块对象。

2.1.2 被导入的名字**必须**由被导入模块导出（`export`）。

2.1.3 `from M import *` 只把名字引入当前文件，不改变当前模块的导出表。

2.1.4 `export from M import …` 把名字同时引入并加入当前模块的导出表。

2.1.5 模块名中的点号属于模块名，不属于成员：`C.math.sin(…)` 不成立；`C` 重导出的名字
写作 `C.sin(…)`。

### 另一个模块的名字怎么写

2.2.1 一条导入决定该模块的名字在导入文件里怎么写，其余因素都不起作用。只有两种写法：

| 声明 | 本文件怎么写该模块的名字 |
| ---- | ------------------------ |
| `import M;` | `M.name` —— `M.String`、`M.print`、`M.IsInteger(T)` |
| `from M import name;` | `name` |
| `from M import *;` | `name` |
| `use M;` | `M.name` |
| `use M as A;` | `A.name` |
| `use M.name;` | `name` |
| `use M.*;` | `name` |

`M.name` 就是 2.1.5 所说的限定写法：点号之前的部分是**模块名**，不是成员的短名。

2.2.2 `import M;` 只绑定 `M` 本身。不带 `M` 写出的成员名不是这门语言里的名字，且**没有任何种类的声明是例外**：
类型、函数、常量、变量、枚举、接口与 trait 都同样取得。`import std;` 之后 `String` 不成立，`std.String` 成立。

2.2.3 `from M import …` 是唯一能不带模块名写成员的方式。它引入的名字属于导入者文件，不属于模块：
本文件的同名声明会遮蔽它们，同一拼写从两个模块各引入一次是诊断。

2.2.4 点号模块名两栏都写全：`import std.string;` 之下类型写作 `std.string.String`，绝不写作 `string.String`。

### `use`

2.3.1 `use` 与 `import` 以同一方式读取模块，区别只在于绑定什么。`use` 声明具有下列形式
之一，每一种都加载它命名的模块：

| 声明 | 本文件中绑定的名字 |
| ---- | ------------------ |
| `use M;` | `M` |
| `use M as A;` | `A` |
| `use M.name;` | `name` |
| `use M.*;` | `M` 导出的每一个名字 |

2.3.2 `use` 声明**必须**命名一个模块。模块名**必须**写在 `use M;`、`use M as A;`、
`use M.*;` 中，以及 `use M.name;` 的模块部分。

2.3.3 `use M as A;`**不得**绑定 `M`。别名 `A`**必须**指代该声明命名的模块。

2.3.4 `use M.*;`**必须**绑定 `M` 导出的每一个名字，且不绑定其他名字。条款 2.1.2 的
规则适用于该形式。

2.3.5 `use` 所绑定的名字**必须**指代 `M` 所导出的那个成员，无论其种类：函数、类型、
枚举、接口、trait、常量或变量。

2.3.6 不带 `export` 的 `use` 声明**必须**只影响写出它的文件；该文件的导出表不变。

2.3.7 带 `export` 的 `use` 声明**必须**同时把绑定的名字加入该文件的导出表。发布的名字为：

| 声明 | 发布的名字 |
| ---- | ---------- |
| `export use M.name;` | `name` |
| `export use M.*;` | `M` 导出的每一个名字 |
| `export use M;` | 无 |
| `export use M as A;` | 无 |

2.3.8 `export use M.name;` 与 `export from M import name;`**必须**在导出表中发布同一个
条目。

## 导出表

### 内容

每种声明都可以导出：

| 声明 | 导入者得到的内容 |
| ---- | ---------------- |
| `export fn f(…) T { … }` | 签名与符号；重载全部保留 |
| `export fn f(…) T;` | 只有声明；符号在别处定义 |
| `export type T { … }` | 字段（含 `mutable` 与 `@align(..)`）、模板参数、特化、嵌套别名 |
| `export type T;` | 名字，作为不完整类型 |
| `export type T<…>` | 类型族：参数与全部特化 |
| `export type T = U;` | 别名 |
| `export union U { … }` | 字段与联合布局 |
| `export enum E { … }` | 类型（基类型）与每个成员的值 |
| `export interface I(it T) { … }` | 方法表 |
| `export traits X(it T) { … }` | 名字；要求随定义模块的语法树 |
| `export NAME const T = v;` | 值与类型 |
| `export name T = v;` | 模块级变量本身 |
| `@cabi export fn f(…) T;` | 外部函数：ABI 与符号 |
| `export name T @cabi;` | 外部变量：名字、类型与链接符号 |
| `export define NAME …` | 宏定义 |

3.1.1 导出不传递：只有 `export from` 才使名字进入本模块的导出表。

3.1.2 调用 `x.f(…)`**必须**在声明 `x` 类型的那个模块所声明的函数中解析 `f`。包含该
调用的文件所导入的函数**不得**参与该解析，书写 `x` 类型时所带的限定**不得**影响该解析。

3.1.2a 成员函数**必须**仅在声明为 `export` 时才能从其模块外调用。未声明 `export` 的
成员函数**不得**成为 3.1.2 的候选。

3.1.2b 声明为 `export` 的成员函数**必须**在接收者类型可被命名的任何文件中可调用。

3.1.3 宏定义随导出表传递；宏体中引用但未导出的宏也随定义一起可用。

### 不完整类型

3.2.1 `export type Node;` 导出名字而非布局。导入者可以使用 `*Node`、`&Node`，
**不得**按值使用或访问成员。

3.2.2 定义可以只在定义模块内可见；这是不透明句柄的规范形式。

3.2.3 `sizeof(Node)`、`Node x;`、`x.field` 要求完整类型；不完整类型上是错误。

## 伞模块

4.1 伞模块由 `export from` 声明组成。

4.2 同名名字的合并规则：函数按重载合并；其他种类以伞模块自己的声明为准，转发
来的同名名字被忽略。

## 模块在哪里找

5.1 `import M;` 的查找顺序为：

1. 导入者所在目录；
2. 环境变量 `FALLTHROUGH_STANDARD` 指向的目录（若设置）；
3. 实现所在目录及其上若干层；
4. 被编译文件所在目录及其上若干层；
5. 当前工作目录及其上若干层。

5.2 点号映射为目录分隔符：`std.string` 对应 `std/string.ftm`。

5.3 每一层目录中，加载器**必须**先查找 `M.<平台>.ftm`，再查找 `M.ftm`。平台名
为目标系统名（如 `linux`、`windows`、`macos`）；模块名不因平台文件而改变。

5.4 实现**必须**允许用环境变量 `FALLC_TARGET_OS` 覆盖检查所用的平台名，以便在
一种系统上检查另一种系统的平台文件。

5.5 一个模块名**必须**只解析出一个文件；两个文件都能提供同一模块名时，实现
**必须**报告诊断。

## 名字身份

6.1 一个模块名只对应一个文件。

6.1.1 模块名在到达它的各条路径上也是稳定的：从 `std` 到达的 `std.array` 与从程序到达的
`std.array` 是同一个模块，只加载一次，只有一张导出表。

6.2 短名属于直接导入者。

6.3 局部值可以遮蔽同名模块名。同名两者并存时，`name.member` 读的是该值的成员：模块
没有值，绑定到值上的名字就不会被读作模块。

6.4 同一模块声明所引入的类型在各翻译单元中是同一类型；分别声明的同名类型是不同
类型。

## 默认值跨模块

7.1 形参默认值是声明它的模块的表达式。

7.2 声明模块**必须**把默认值记录随导出签名保留；调用方按该记录填充省略的实参。

7.3 因此跨模块调用可以省略带默认值的实参。

7.4 实现**不得**要求调用方重写默认值。

## 多文件编译

8.1 一个程序可以由多个翻译单元组成，一起编译并链接。

8.2 每个 `.ft` 文件是一个翻译单元；翻译单元之间不共享名字，除非通过导入。

8.3 一个符号在整个程序中**至多**定义一次；声明可以重复。

8.4 `.ftm` 文件通过 `import` 参与编译；它**不得**被单独链接为程序。

## 预编译模块文件

10.1 实现**可以**把模块的导出表缓存成文件，读回来代替重做解析、名字解析与声明检查。
该缓存是优化手段：程序的含义**不得**取决于该文件是否存在。

10.2 出现下列任一情况时，缓存表**必须**被拒绝，改为从源码编译该模块：

- 文件由另一个编译器构建或另一个格式版本写出；
- 文件记载的指针宽度或对象模型不同；
- 模块自身源码的哈希与记载的不符；
- 表无法解码。

10.3 模块的缓存表**必须**以该模块自身源码为键，**不得**以它的依赖为键。模块导出什么是
它自己文本的性质；依赖在它之下发生变化，只在该模块随之被修改时才有影响。

10.4 记录**必须**携带该表编译时所用的一组模块，读取者在使用该表之前**必须**先加载这些
模块：表里的类型名要靠它们解析。

10.5 表**必须**携带其目标文件编译时所用的键。代码生成以模块库所含模块的集合为键，而该
集合无法只从一张表推导出来。

10.6 对象缓存的键是模块**集合**的函数，不是加载顺序的函数。到达同一集合的两条路径
**不得**产生两个库。

10.7 对于在两次编译之间修改自己源码的调用方，该缓存**必须**可以关闭。

## 外部库

9.1 `link` 声明要链接的外部库：

```ft
link m dynamic from default;
link z static from "/usr/lib";
link "gcc_s" dynamic from default;

fn main() int {
    return 0;
}
```

这三个文件都能编译并链接：裸名字按链接器的方式查找库，带引号的名字原样传给链接器，
`from "…"` 指定查找目录。

9.2 `link` 的三部分**必须**齐全：名字、链接方式（`dynamic` 或 `static`）、查找
位置（`default` 或目录字符串）。

9.2.1 `dynamic` 与 `static` **不是**保留字（见
[01 词法 §5.2](01-lexical.zh.md#关键字)）。它们只在 `link` 声明中库名之后的位置表示
链接方式；在其他任何位置都是普通标识符，所以程序可以声明 `static int = 2;` 并使用它。
声明中的静态存储期是属性 `@static`（见
[03 声明 §4](03-declarations.zh.md#声明修饰符)），那是不同位置的另一个词。

9.3 库名含 `/` 或以 `.a`/`.so` 结尾时，作为文件路径交给链接器；否则按平台约定
加前缀与后缀。

9.4 外部函数与外部变量的声明分别见 [04 函数](04-functions.zh.md) 与
[03 声明](03-declarations.zh.md#外部变量与外部函数)。

9.5 标准库的 C 绑定是普通模块；导入方式与普通模块相同。
