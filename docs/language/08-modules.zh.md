# 08 模块

> [English](08-modules.md)

## 范围

本篇规定模块的导入与导出、导出表的内容、名字身份规则、模块查找顺序、多文件编译
与链接。

## 导入

### 形式

```ft
import geom;
import geom as g;
from geom import area, Point;
from geom import *;
export from geom import *;
export from geom import area;
```

2.1.1 导入是静态的：模块在编译期加载，不存在运行期模块对象。

2.1.2 被导入的名字**必须**由被导入模块导出（`export`）。

2.1.3 `from M import *` 只把名字引入当前文件，不改变当前模块的导出表。

2.1.4 `export from M import …` 把名字同时引入并加入当前模块的导出表。

2.1.5 模块名中的点号属于模块名，不属于成员：`C.math.sin(…)` 不成立；
`C` 重导出的名字写作 `C.sin(…)`。类型名是例外：`std.string.String` 是合法写法，
因为整条路径即类型的名字。

### 短名：类型名字和值名字不一样

2.2.1 `import M;` 之后，`M` 导出的**类型名**（`type`、`union`、`enum`、
`interface`、`traits`）可以直接写短名。

2.2.2 **函数、常量、模块级变量没有短名例外**：它们必须用限定名，或通过
`from M import name` 引入。

2.2.3 短名只属于**直接**导入该模块的文件；传递依赖只暴露全名。

2.2.4 点号模块的最后一段是其短名，但只对直接导入者有效。

## 导出表

### 内容

每种声明都可以导出：

| 声明 | 导入者得到的内容 |
| ---- | ---------------- |
| `export fn f(…) T { … }` | 签名与符号；重载全部保留 |
| `export fn f(…) T;` | 只有声明；符号在别处定义 |
| `export type T { … }` | 字段（含 `mutable` 与 `@align(..)`）、模板参数、特化、嵌套别名 |
| `export type T;` | 名字，作为不完整类型 |
| `export type T<…>` | 类型族：参数与全部特化 |
| `export type T = U;` | 别名 |
| `export union U { … }` | 字段与联合布局 |
| `export enum E { … }` | 类型（基类型）与每个成员的值 |
| `export interface I(it T) { … }` | 方法表 |
| `export traits X(it T) { … }` | 名字；要求随定义模块的语法树 |
| `export NAME const T = v;` | 值与类型 |
| `export name T = v;` | 模块级变量本身 |
| `@extern_C export fn f(…) T;` | 外部函数：ABI 与符号 |
| `export name T @extern_C;` | 外部变量：名字、类型与链接符号 |
| `export define NAME …` | 宏定义 |

3.1.1 导出不传递：只有 `export from` 才使名字进入本模块的导出表。

3.1.2 类型的方法**必须**单独 `export`；只导出字段时，导入者不能调用成员函数。

3.1.3 宏定义随导出表传递；宏体中引用但未导出的宏也随定义一起可用。

### 不完整类型

3.2.1 `export type Node;` 导出名字而非布局。导入者可以使用 `*Node`、`&Node`，
**不得**按值使用或访问成员。

3.2.2 定义可以只在定义模块内可见；这是不透明句柄的规范形式。

3.2.3 `sizeof(Node)`、`Node x;`、`x.field` 要求完整类型；不完整类型上是错误。

## 伞模块

4.1 伞模块由 `export from` 声明组成。

4.2 同名名字的合并规则：函数按重载合并；其他种类以伞模块自己的声明为准，转发
来的同名名字被忽略。

## 模块在哪里找

5.1 `import M;` 的查找顺序为：

1. 导入者所在目录；
2. 环境变量 `FALLTHROUGH_STANDARD` 指向的目录（若设置）；
3. 实现所在目录及其上若干层；
4. 被编译文件所在目录及其上若干层；
5. 当前工作目录及其上若干层。

5.2 点号映射为目录分隔符：`std.string` 对应 `std/string.ftm`。

5.3 每一层目录中，加载器**必须**先查找 `M.<平台>.ftm`，再查找 `M.ftm`。平台名
为目标系统名（如 `linux`、`windows`、`macos`）；模块名不因平台文件而改变。

5.4 实现**必须**允许用环境变量 `FALLC_TARGET_OS` 覆盖检查所用的平台名，以便在
一种系统上检查另一种系统的平台文件。

5.5 一个模块名**必须**只解析出一个文件；两个文件都能提供同一模块名时，实现
**必须**报告诊断。

## 名字身份

6.1 一个模块名只对应一个文件。

6.2 短名属于直接导入者。

6.3 局部值可以遮蔽同名模块名。

6.4 同一模块声明所引入的类型在各翻译单元中是同一类型；分别声明的同名类型是不同
类型。

## 默认值跨模块

7.1 形参默认值是声明它的模块的表达式。

7.2 声明模块**必须**把默认值记录随导出签名保留；调用方按该记录填充省略的实参。

7.3 因此跨模块调用可以省略带默认值的实参。

7.4 实现**不得**要求调用方重写默认值。

## 多文件编译

8.1 一个程序可以由多个翻译单元组成，一起编译并链接。

8.2 每个 `.ft` 文件是一个翻译单元；翻译单元之间不共享名字，除非通过导入。

8.3 一个符号在整个程序中**至多**定义一次；声明可以重复。

8.4 `.ftm` 文件通过 `import` 参与编译；它**不得**被单独链接为程序。

## 外部库

9.1 `link` 声明要链接的外部库：

```ft
link m dynamic from default;
link z static from "/usr/lib";
link "gcc_s" dynamic from default;
```

9.2 `link` 的三部分**必须**齐全：名字、链接方式（`dynamic` 或 `static`）、查找
位置（`default` 或目录字符串）。

9.3 库名含 `/` 或以 `.a`/`.so` 结尾时，作为文件路径交给链接器；否则按平台约定
加前缀与后缀。

9.4 外部函数与外部变量的声明分别见 [04 函数](04-functions.zh.md) 与
[03 声明](03-declarations.zh.md#外部变量)。

9.5 标准库的 C 绑定是普通模块；导入方式与普通模块相同。
