# 07 异常

> [English](07-exceptions.md)

## 范围

本篇规定异常模型：可能抛出的声明、`raise`、`try` 的各子句、调用点义务、异常的
传播与析构顺序，以及实现附带标准库对资源不足的处理策略。

## 模型

2.1 异常是本规范规定的**返回值的一部分**，不是独立的控制流机制。

2.2 一个可能抛出的函数的返回值是一个带标签的联合：

- 返回 `T` 的函数：`{ ok, value T, exception }`；
- 不返回值的函数：`{ ok, exception }`。

2.3 异常由两个字符串分量组成：**类型名**与**消息**。两者的类型由标准库规定。

2.4 实现**必须**保证：可能抛出的调用点只增加一次标签判断；抛出不需要栈展开表，
也不改变不抛出函数的 ABI。

2.5 异常离开作用域时，该作用域内已构造的绑定**必须**按 [09 作用域](10-scopes.zh.md)
规定的顺序销毁。

## 声明可能抛出

3.1 `except` 写在返回类型之后。

```ft
import C;

fn risky(n int) int except {
    if (n < 0) {
        raise "ValueError": "negative";
    }
    return n * 2;
}

fn main() int {
    C.printf("%d\n", risky(3)!!);
    return 0;
}
```

该程序输出 `6`：调用处标了 `!!`，一旦真的抛出就停下程序。

3.2 `except` 之后可以写条件：一个常量表达式，说明仅当条件成立时函数可能抛出。

```ft
import C;

fn check(n int) int except(n < 0) {
    if (n < 0) {
        raise "ValueError": "negative";
    }
    return n;
}

fn main() int {
    C.printf("%d\n", check(5)!!);
    return 0;
}
```

该程序输出 `5`。条件 `n < 0` 在每个调用点折叠：实参是常量时它当场决定，所以 `check(5)`
不需要处理者。

3.3 条件以形参命名。调用点用实参把条件折成常量：实参均为常量时实现**必须**当场
判定；实参不是常量时按可能抛出处理。

3.3.1 `except(auto)` 不写条件：函数体能不能抛出，就是函数能不能抛出。决定权在函数体，
所以体内没有任何抛出操作的函数不会抛出，对它写 `!!` 的调用处会被告知这一点（`S0083`）。

```ft
import C;

fn risky(n int) int except(auto) {
    if (n < 0) { raise "ValueError": "negative"; }
    return n * 2;
}

fn calm(n int) int except(auto) {
    return n + 1;
}

fn main() int except {
    C.printf("%d %d\n", risky(3)!!, calm(1)!!);
    return 0;
}
```

该程序输出 `6 2`：`risky` 的体里有 `raise`，所以它是可能抛出的；`calm` 的体里没有，
所以它不是——调用处写 `calm(1)!!` 会被指出这个 `!!` 没有作用。

3.3.2 `except(auto)` 与写出条件的 `except` 是同一个问题的两种问法，同一个函数两种都可写。
`!!` 不计入可能抛出：该标记让程序在那就是停下来，没有任何异常经由它离开函数。

3.4 函数体内任何可能抛出的操作（直接的 `raise`、可能抛出的调用、可能抛出的隐式
调用）都要求函数声明 `except`，否则实现**必须**报告诊断。

## 抛出

4.1 `raise "Type": "message";` 抛出异常；`raise "Type";` 省略消息；`raise;` 重新
抛出当前正在处理的异常。

4.2 类型名与消息**必须**可转换为标准库的字符串类型；字符串字面量自动完成该转换。

4.3 消息可以是由运行期值构造的文本。

4.4 `raise` 只能出现在可能抛出的函数中。

4.5 裸 `raise;` 只能出现在处理异常的 `except` 块内；其类型与消息保持不变。

## 捕获

### 形式

```ft
import C;

fn half(n int) int except {
    if (n % 2 != 0) {
        raise "ValueError": "odd";
    }
    return n / 2;
}

fn main() int {
    try {
        C.printf("%d\n", half(4)!!);
    } except {
        C.printf("caught\n");
    } else {
        C.printf("no raise\n");
    } finally {
        C.printf("done\n");
    }
    return 0;
}
```

该程序依次输出 `2`、`no raise`、`done`：主体产出了值，所以 `else` 执行；而 `finally`
无论发生了什么都会执行。

| 子句 | 语义 |
| ---- | ---- |
| `try` | 受保护语句块 |
| `except` | 一个或多个 `except` 子句，按书写顺序尝试，第一个匹配的执行；裸 `except` 捕获全部，括号内列出名字时只捕获这些异常（5.6） |
| `else` | `try` 块未抛出时执行 |
| `finally` | 无论是否抛出都执行 |

5.2 `except` 块通过标准库的异常访问函数取得当前异常。该值的类型与访问方式由
标准库规定。

5.3 没有 `except` 的 `try` 只是一个作用域。

5.4 只带 `finally` 的 `try` 不捕获异常；异常向外传播，`finally` 先执行。

5.5 `else` 与 `finally` 的执行顺序为：`try` 成功 → `else` → `finally`；抛出时
→ `except` → `finally`。

### 具名捕获

5.6 `try` 之后可以有**任意多个** `except` 子句，按书写顺序从上到下尝试，第一个
匹配子句的块被执行：

```ft
import C;

fn lookup(key int) int except {
    if (key == 1) { raise "KeyError": "missing"; }
    if (key == 2) { raise "FileError": "bad"; }
    return key;
}

fn classify(key int) int except {
    try {
        return lookup(key)??;
    } except ("KeyError") {
        return -1;
    } except ("IOError", "FileError") {
        return -2;
    } except {
        return -3;
    } finally {
        C.printf("done %d\n", key);
    }
}

fn main() int except {
    C.printf("%d %d %d\n", classify(0)!!, classify(1)!!, classify(2)!!);
    return 0;
}
```

该程序依次输出 `done 0`、`done 1`、`done 2`，再输出 `0 -1 -2`：子句按书写顺序尝试，
含多个名字的子句接受其中任意一个（`classify(2)` 抛出的正是第二个子句的第二个名字
`FileError`），而 `finally` 在每条路径上都执行。

每个子句有两种写法：

- `except ("ZeroError", "KeyError") { … }`：只捕获名字列出的异常；名字是字符串
  字面量，比较的是异常的**类型名**（`name()`）。
- `except { … }`：裸子句，捕获全部异常。

5.7 没有被任何子句匹配的异常不被该 `try` 捕获：它照常向外传播，本 `try` 的
`finally` 先执行，`else` 不执行。裸 `except` 之后写出的子句永远不会被执行。

5.8 若 `except` 子句都不是裸的，则捕获不完整，只在可能抛出的函数中有意义：在不抛出
的函数里写这样的 `try` 是实现**必须**报告的诊断（要完整捕获，至少要有一个裸
`except` 子句）。块内求值可能抛出的表达式时仍视为已保护；未匹配的异常按 5.7
离开函数。

## 求值点义务

6.1 求值一个可能抛出的**表达式**时**必须**满足下列之一（不限于函数调用：运算符、
下标、构造、显式与隐式转换以及赋值同样适用）：

1. 位于带 `except` 的 `try` 块内；
2. 在其后写 `??`，把异常交给本函数的调用者；
3. 在其后写 `!!`，让程序带着异常报告停下。

6.2 可能抛出却不满足这三者之一的表达式是**未处理的调用点**，实现**必须**报告诊断。

### `??` —— 传出去

6.3 `??` 是后缀表达式：`x??` 等价于 `try { x } except { raise; }`。

6.4 `??` 只影响当前调用点；同一函数内更外层的 `try` 可以捕获它。

6.5 `??` 用于不可能抛出的表达式是警告（`S0083`），不是错误：模板实例化中同一
标记可能同时用于可能抛出与不可能抛出的表达式。

6.6 表达式的结果被使用时，`??` 保留该值：`v int = f(n)??;` 中 `v` 持有 `f` 的结果，
或者异常离开本函数。结果不被使用时效果相同，因为传出的异常从不会被丢弃。

### `!!` —— 就地停下

6.7 `!!` 是后缀表达式：`x!!` 等价于 `try { x } except { std.panic(); }`。`??` 把异常
交给调用者，`!!` 则结束程序。

6.8 `!!` **不**要求所在函数声明 `except`：既然程序已经停下，就没有东西离开该函数。因此它在
自身不会抛出的函数里也合法——这正是读者该注意到的区别：`??` 是对调用者的声明，`!!` 是对
程序本身的声明。

6.9 报告**必须**写明异常类型与消息，程序**必须**异常终止而不是返回状态码：这是一次停下，
不是把一个失败返回出去。报告的具体形式由实现决定，但异常有消息时**必须**包含类型名与消息，
形状与 8.1 的未捕获报告一致。

6.10 `!!` 用于不会抛出的表达式时没有作用，实现**必须**警告（`S0083`，`useless-raise-mark`），
与没有东西可传的 `??` 完全一样：标记声称程序会在此停下，而对这个表达式并不成立。之所以是
警告而非错误，是因为在模板中同一个 `!!` 可能对某些实例化会抛出、对另一些不会。

6.11 写 `??` 还是 `!!` 是程序自己做的设计决定：失败该由调用者处理时写 `??`，不值得处理时
写 `!!`。库**应**用 `??` 把选择留给调用者；应用**可以**在自己认定失败即终止之处用 `!!`。

### 两个标记

6.12 `??` 与 `!!` 是仅有的两个后缀标记。单独的 `?` 属于条件运算符，读作
`cond ? then : else`，因此双字符标记不会被误认为它。

## 隐式调用点

7.1 下列构造会调用成员函数，因此也是调用点：构造、赋值、运算符、下标、类型转换、
条件中的 `__bool__`、`__call__`、`str()`、`repr()`。

7.2 初始化器上的 `??` 或 `!!` 保护整条初始化，包括实现为初始化插入的构造调用。写成类型的
绑定（`T x = expr??;`）与推导类型的绑定（`x auto = expr??;`）都适用；两种情况里标记
都覆盖初始化器所经历的构造器查找。

7.3 赋值上的 `??` 或 `!!` 只属于右值表达式；赋值运算符自身可能抛出时，该赋值是未处理
的调用点。

7.4 其他隐式调用的调用点位于该表达式的位置；需要保护整条语句时**必须**使用
`try` 区域。

## 未捕获异常

8.1 程序未捕获的异常**必须**由实现报告到标准错误，并在报告后以退出码 70 结束。

8.2 报告的格式**应**包含异常类型名与消息。

## 资源不足（实现附带标准库的策略）

9.1 标准库的容器与字符串在分配失败时的行为由标准库规定；本规范不要求其成员
函数标注 `except`。

9.2 实现**必须**保证：构造异常记录本身失败时不得产生未定义行为；具体的替换策略
由标准库规定。

9.3 程序自行 `raise` 的可恢复错误是本规范规定的异常使用场景；资源不足的处理策略
不属于语言语义。
