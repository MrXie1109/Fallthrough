# 附录 C 属性

> [English](appendix-c-attributes.md)

## C.1 范围

本附录汇总语言接受的全部属性：写在哪里、含义是什么、约束是什么。规范性正文见
[03 声明 §9](03-declarations.zh.md#属性)；本附录只是参考表，不创造任何规则。

## C.2 通则

C.2.1 属性写作 `@name` 或 `@name(参数)`，作用于它所在的声明或分支。

C.2.2 属性出现在不允许的位置、名字未知、重复、参数个数或种类不对，都是错误；实现
**不得**静默忽略（[03 声明 §9.3](03-declarations.zh.md#属性)）。

C.2.3 属性是**请求**，而不是调用方可依赖的承诺：`@inline` 与 `@cold` 只是建议，符合
规范的实现可以忽略。

## C.3 函数

| 属性 | 参数 | 含义 |
| ---- | ---- | ---- |
| `@inline` | — | 请求内联；代码生成仍可拒绝 |
| `@noinline` | — | 请求不要内联 |
| `@noreturn` | — | 函数从不正常返回；返回类型**必须**是 `void` |
| `@must_use` | — | 调用的结果**必须**被使用；丢弃会警告 |
| `@cold` | — | 函数很少被调用；代码生成可把它放到慢路径 |
| `@deprecated` | — 或一个字符串 | 每次使用都警告；给出字符串时作为消息 |
| `@enable_if(cond)` | 一个条件 | 仅当 `cond` 为真时该声明存在；`cond` **必须**是编译期常量 |
| `@constexpr` | — | 该函数可在常量位置被调用 |
| `@extern_C` | — | 使用 C ABI：符号不做名称修饰 |

C.3.1 把 `@noreturn` 用在返回类型不是 `void` 的函数上是错误。

C.3.2 `@enable_if` 按实例化逐个判定。对模板而言，它用推导出的实参求值——这正是某个
成员对某些实参存在、对另一些不存在的实现方式。

## C.4 变量与常量

| 属性 | 参数 | 含义 |
| ---- | ---- | ---- |
| `@inline` | — | 同一个变量可以定义在多个翻译单元中 |
| `@deprecated` | — 或一个字符串 | 每次使用都警告 |
| `@align(N)` | 一个整数 | 对齐要求（字节）；`N` **必须**是 2 的幂 |
| `@constexpr` | — | 需要编译期常量初始化器；该绑定同时是 `const` |
| `@static` | — | 静态存储期（生命周期超出其作用域的局部变量） |
| `@thread_local` | — | 每个线程一个对象 |
| `@uninitialized` | — | 不清零、不做默认构造；**不允许**初始化器；**仅限局部** |
| `@maybe_unused` | — | 不报告“从未被读取”的警告 |
| `@extern_C` | — | 变量的存储属于另一种语言，按未修饰的名字查找 |

C.4.1 把 `@uninitialized` 用在模块级变量上是错误：该变量位于程序映像中，加载器在程序
启动前会将其清零，因此不存在“内容可以不管”的存储。

C.4.2 `@uninitialized` 与初始化器不能同时写。

## C.5 类型

| 属性 | 适用于 | 含义 |
| ---- | ------ | ---- |
| `@deprecated` | 类型、类型家族、trait、接口、枚举、别名 | 每次使用都警告 |
| `@must_use` | 类型声明 | 返回该类型的调用**必须**使用其结果 |

C.5.1 `export` 不属于本附录意义上的属性，尽管它与属性写在同一位置：它是声明自身语法
的一部分（[08 模块](08-modules.zh.md#导出表)）。

## C.6 分支

| 属性 | 位置 | 含义 |
| ---- | ---- | ---- |
| `@likely` | `if`、`else`、`case` | 该分支通常被选中 |
| `@unlikely` | `if`、`else`、`case` | 该分支很少被选中 |
| `@constexpr` | 仅 `if` 的条件之后 | 条件**必须**是编译期常量，且未选中的分支不会被检查 |

C.6.1 `@constexpr` 的 `if` 是程序在编译期选择代码的方式：未选中的分支仍须能解析，
但不做类型检查，因此它可以提到对当前构建而言并不存在的东西。

C.6.2 `@likely` 与 `@unlikely` 不携带程序可观察到的语义；它们是对生成代码布局的提示。
